# 模块计划 03 — AI 代理与基准测试（Day 7-9）

## 0. 博弈性质定性（设计的理论基础）

最初稿把本游戏定性为"非完美信息、需要 ISMCTS"，这是**错的**，修正如下：

- 袋中剩余方块的**构成完全可推算**：100 块减去网格、备料行、罚分行、展台、中央池、弃料盒中所有可见方块。双方视角信息完全对称，不存在私有信息。
- 随机性只来自**抽取顺序**（每轮开始填展台、袋空洗回）。
- 因此这是**完美信息随机博弈**（类似西洋双陆棋），且**一轮之内是纯确定性完美信息博弈**——展台一旦摆好，到轮末没有任何随机事件。

设计结论：
1. **轮内 Minimax 完全成立**，无需任何信息集处理。
2. 跨轮搜索只需处理**机会节点**（洗袋抽料），用确定化采样即可；ISMCTS 是不必要的复杂化。
3. 一轮通常 8~12 步（20 块被分批取完），轮末是天然的搜索边界与评估点。

## 0.1 本阶段的工作方式（v3 关键变化）

三级 AI **串行落地，每级落地当天接入 P2 的网页**：

```
Greedy 写完 → 接入网页 → 你打两局 → 主观反馈（"它老是白送地板分" / "太贪短期分了"）
           → 调评估函数 → benchmark 复核胜率 → 进入 Minimax
```

评估函数的权重调参靠**你的主观棋感 + benchmark 胜率**双通道反馈。纯数据调参容易陷入"两个都很弱的 AI 互相刷胜率"的局部最优，人眼能一句话点破。

## 1. 统一接口（ai/base.py）

```python
class Agent(ABC):
    name: str
    def choose(self, state: GameState, legal: list[Action], rng: random.Random,
               deadline: float | None = None) -> Action: ...
    # deadline = time.monotonic() 截止时刻；None 表示不限时
```

约束：Agent **绝不修改**传入的 state（内部用 clone 或 apply/undo）；自带 rng 保证基准可复现；所有 Agent 必须在 deadline 前返回（超时返回当前最优）。

## 2. 共享评估函数（ai/evaluate.py）

Greedy 打分、Minimax 叶节点、MCTS rollout 截断都用同一个函数，集中调参：

```python
def evaluate(state: GameState, player: int) -> float:
    return side_value(state, player) - side_value(state, 1 - player)
```

`side_value` 的组成项（权重为初始值，本阶段调参）：

| 项 | 计算 | 初始权重 |
|----|------|---------|
| 实际分数 | `board.score` | 1.0 |
| 轮末预计得分 | 假设本轮立即结算：满行上格的即时分 + 罚分（**精确模拟，不是近似**） | 1.0 |
| 备料行进度 | 每条非空未满行按 `count/capacity` 计值；**下轮无法完成的行（所需色余量不足）打折** | 0.3 |
| 相邻潜力 | 已上格方块的空邻格数（未来连击潜力） | 0.1 |
| 终局加分进度 | 横行/竖列/同色完成度的**凸函数**（已集 4/5 色远高于 2/5 的两倍） | 行 0.4 / 列 1.5 / 色 2.0 |
| 罚分风险 | 当前罚分行已占槽的下一槽罚分绝对值 | 0.2 |

实现要求：一次遍历完成，无内存分配热点；单次 < 20µs。

## 3. 各级 Agent

### Level 0 — RandomAgent
`rng.choice(legal)`。用途：引擎 fuzz、基准下界。约 10 行（P2 已用到）。

### Level 1 — GreedyAgent（Day 7）
对每个合法动作：clone → apply → `evaluate` → 取最大（平分时 rng 打破）。
可选噪声参数 `epsilon`（以 ε 概率随机走），供 MCTS rollout 与调参用。预计每步 < 5ms。

**落地即接入网页**，你打两局给反馈，调完权重再往下走。

### Level 2 — MinimaxAgent（Day 8）
- **搜索域**：仅当前轮（轮内纯确定性）。深度默认 4 半步；搜索到达轮末（展台+中央池清空）时，在该节点**精确执行 settle_round 模拟**后调 evaluate——不跨入下一轮（下轮开局是机会节点，收益递减）。
- **α-β 剪枝 + 走法排序**：子节点按 Greedy 单步评估降序展开。分支因子 30~80，排序对剪枝效率至关重要。
- **迭代加深 + deadline**：depth=2 起逐层加深，超时返回最近完成层的最优。
- 置换表：轮内状态重复率低，先不做，留 TODO 与接口。
- 对抗性策略（卡对手所需颜色、迫使对手吃罚分）**无需特判**——评估函数是零和差值，搜索自然涌现。这一点值得在网页上专门验证：故意留一堆某色给它，看它会不会卡你。

预计每步 50~300ms（深度 4 含排序）。

### Level 3 — MctsAgent（Day 9）
- **UCT**：`Q + c·sqrt(ln N / n)`，c 默认 1.2（调参项）。
- **跨轮处理**：当某动作把本轮打完时，其后是机会结果——采用**每次模拟独立确定化**（open-loop）：本次 playout 经过轮边界时用独立 rng 现场抽料开新轮，同一树节点聚合不同抽料结果的统计量。这比为每个抽料结果单独建节点更抗组合爆炸。
- **Rollout**：`GreedyAgent(epsilon=0.15)` 走到终局或最多 2 个轮末，截断处用 evaluate 归一化到 [-1,1]。
- **根节点并行**（可选，本阶段末尾）：多进程各建独立树后合并访问计数。先单线程达标。
- 时间预算：deadline 驱动，默认 500ms；报告每步平均模拟次数（目标 > 2000 次/步）。

### 自检
每个 Agent 一个 smoke 测试：与 Random 各打 20 局不崩溃、不超时、动作全合法。

## 4. 基准测试（scripts/benchmark.py）

```bash
python -m scripts.benchmark --p0 greedy --p1 minimax --games 500 --seed 42 --swap
```

- **公平性**：`--swap` 使双方各执先手一半局数；每局 seed = base_seed + i，两两配对使用**相同料序**（配对样本降方差）。
- **输出**：胜/平/负、平均得分与分差、每步平均/最大决策耗时、95% 置信区间（正态近似）；结果追加写入 `docs/ai_benchmarks.md`。
- **多进程**：`--workers N`（局与局独立）。

## 5. 出口条件（自动化 + 人工双通道）

| 对阵 | 要求（500 局、swap） |
|------|----------------------|
| Greedy vs Random | 胜率 > 90% |
| Minimax(d4) vs Greedy | 胜率 > 65% |
| MCTS(500ms) vs Minimax(d4) | 胜率 ≥ 55% |
| 所有 Agent | 每步 ≤ 500ms（MCTS 按预算自截断） |

外加人工验证：
- [ ] **你在网页上分别打过三级 AI**，主观确认难度梯度合理（Greedy 能赢、Minimax 吃力、MCTS 难赢）
- [ ] Minimax 表现出可观察的对抗行为（会卡你需要的颜色、会在合适时机倾销）
- [ ] 没有明显的"蠢招"（无意义地吃大罚分、放弃唾手可得的连击）

若 MCTS 达不到胜率线：优先排查 rollout 质量与轮边界确定化，其次调 c 与评估权重；保留"Minimax 即最高难度"作为降级方案，不阻塞 P4。
